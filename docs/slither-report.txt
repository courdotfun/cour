ROOT CAUSE for the dead-code / constable-states / immutable-states / uninitialized-state cluster
------------------------------------------------------------------------------------------------
This codebase MUST compile with `via_ir = true` (v4-core Pool.sol + the curve/hook locals exceed the
EVM stack otherwise — see CLAUDE.md / foundry.toml). Slither's state-write / call-graph dataflow is
incomplete on via-IR output, so it fails to see writes performed in constructors, `initialize()`, and
`wire()`, and fails to see internal calls.

Smoking gun: slither reports `COURFactory.poolManagerC` (an `immutable` set in the constructor at
COURFactory.sol:83) as "never initialized" (slither-raw.txt:104). That is impossible for an immutable —
it proves slither's write-tracking is unreliable here. Every dead-code / constable / immutable /
uninitialized-state finding below is the same artifact and is refuted by a concrete write/call site.
The full test suite (unit + fuzz + invariant + integration, 100+ tests) exercises all of these paths.

Detector: constable-states / immutable-states / uninitialized-state — ALL FALSE POSITIVES
-------------------------------------------------------------------------------------------------
- COURCurve.{token,stock,creator,_feeBps,_launchedAt,_stockDecimals,_mode,_vS,_vT,_k,_vTStop,_vS0,_vT0}
  are per-clone STORAGE written in COURCurve.initialize() (COURCurve.sol:61-73). They cannot be
  constant/immutable: COURCurve is an EIP-1167 minimal-proxy implementation and every clone sets its
  own values via initialize(); an immutable would bake a single value into the shared implementation.
- COURCurve._initialized: written in the constructor (51) AND initialize() (60) — not immutable.
- COURFeeVault.{factory,hook,router,priceReader,_wired}: written in wire() (COURFeeVault.sol:75-79),
  post-deploy (the factory/hook/router deploy after the vault). treasury: constructor + setTreasury().
- COURFactory.{startMcUsd,gradMcUsd,minRefLiqUsd,launchFee}: INTENTIONALLY mutable — admin tunes them
  for FUTURE launches via setLaunchParams() (COURFactory.sol:257-260). Making them immutable would
  break that feature (proven by test_setLaunchParams_new_launch_uses_new_values).
- COURFactory.{poolManagerC,positionManager,hookC,feeVaultC,priceReaderC,curveImpl}: immutables set in
  the constructor (COURFactory.sol:83-88). The "uninitialized-state" flag on these is the via-IR artifact.
- All mappings (curveOf, _config, _poolId, _td, stockAllowed, platformOwed, launchAllowlist, ...) are
  written across the normal flows; mappings cannot be constant/immutable.

Other detectors (unchanged triage; no High/Medium)
-------------------------------------------------------------------------------------------------
- reentrancy-events (COURHook beforeSwap/afterSwap/_notify, COURFactory.setStock): COSMETIC. These emit
  events after an external call. All state-mutating paths are protected by ReentrancyGuardTransient and
  the v4 PoolManager lock; no state is read-then-written across the call. No exploitable reentrancy.
- timestamp: BY DESIGN. The spec mandates block.timestamp (Robinhood Chain has sub-second blocks, so
  block numbers are unusable). Lint `block-timestamp` is excluded in foundry.toml for the same reason.
- divide-before-multiply (COURHook tick alignment `(MIN_TICK/spacing)*spacing`): intentional tick
  rounding to a spacing multiple; exact and lint-disabled inline.
- incorrect-equality (`fee==0`, `span==0`): benign exact-zero short-circuits.
- locked-ether:
  * COURFactory.createToken is payable but requires `msg.value == launchFee` (== 0 in Phase 1); any
    non-zero value reverts WrongLaunchFee, so the factory can never custody ETH.
  * COURRouter.buyWithETH deposits the full msg.value into WETH and swaps it; the §2.4 rewrite also
    refunds any residual ETH/WETH so the router never retains funds between txs.
- uninitialized-local (COURHook.beforeInitialize tok/stk/tokenIsZero): assigned on every branch before
  use (the else-branch reverts BadPoolKey); false positive.
- unused-return / shadowing-local / events-maths / missing-zero-check / cyclomatic-complexity:
  informational; reviewed, no action required (constructors already zero-check the critical addresses).
