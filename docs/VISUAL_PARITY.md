## State & roadmap (2026-11-17)

**Infrastructure in place** (this is the start of the fix loop, not the end):
- v8 `#stage` + `fitStage` sizing replicated (`app/lib/stage.ts`) — the app now lays
  out at 1920px and scales to the viewport exactly like v8.
- Fixture mode (`NEXT_PUBLIC_VISUAL_FIXTURE=1`) serves the SAME demo tokens as v8
  (`app/lib/fixture.ts`, extracted verbatim) so screenshots are comparable.
- `app/test/parity.mjs`: freezes animations, waits fonts/images, dismisses v8's
  first-visit risk gate (`cour-risk-ok-v1`), masks §4 + not-yet-ported regions,
  pixelmatch per (view × theme × width × dpr) → this report + diff PNGs.

**Baseline (home only, dpr 1, 15 widths × 3 themes):** classic avg ~12% (best 5.8%
@1920), cartoon/light avg ~23%. 0/45 within the 0.1% bar. Biggest remaining diffs:
1. **Promo orbit** — v8 injects the stock-logo coins via JS; the app renders a static
   orbit. Port the coin markup/animation.
2. **Top traders / news-panel / bottom nav / Oink** — not yet ported (currently
   masked); porting them removes the masks and the surrounding layout shift.
3. **tk-stats / About grid** markup is approximated, not byte-identical to v8's.
4. Sub-pixel font/anti-aliasing on dense text (the thin red edges in the diff PNGs).

**Loop to close it (per view): ** port the exact v8 markup for the remaining
sections → re-run `parity.mjs` → fix the largest diff region → repeat until ≤0.1%,
then unmask and extend to token/create and the rest. dpr 2 + the full state matrix
(modals, ⌘K, QR, tour, hover/focus) are configured but pending the view ports.

> Honest status: the app is **not yet pixel-identical** — this measures the gap and
> drives the work. Current preview still uses REAL data (fixture is build-flag-gated,
> never deployed).
